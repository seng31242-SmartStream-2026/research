# Research

**Project:** SmartStream – Integrated Business Management System  
**Course:** SENG 31242 – System Design Project  
**Group:** Group 07 – NextGen Developers  
**Organisation:** University of Kelaniya, Faculty of Science – Software Engineering Teaching Unit

---

## Purpose

This repository holds all research and fact-finding artefacts gathered during the requirements engineering phase of the SmartStream project. Content here provides the evidential foundation for the Software Requirements Specification (SRS).

---

## Repository Structure

```
research/
├── literature-review/
│   └── *.md                        # Literature review notes and summaries
├── competitive-analysis/
│   ├── competitive-analysis.md     # Feature comparison matrix and gap analysis
│   └── screenshots/                # Screenshots of competing systems (labelled)
├── client-interviews/
│   ├── interview-guide.md          # Structured interview questions used
│   ├── interview-01-transcript.md  # Transcript or summary of Interview #1
│   ├── interview-02-transcript.md  # Transcript or summary of Interview #2
│   └── key-findings.md             # Consolidated key findings across sessions
├── surveys/
│   ├── survey-instrument.md        # Survey questions
│   └── survey-responses-summary.md # Anonymised responses and statistical summary
├── document-analysis/
│   └── *.md                        # Notes from existing system documents reviewed
└── workshops/
    ├── agenda.md                   # Workshop agenda
    ├── attendance.md               # Attendance sheet
    └── outputs/                    # Affinity maps or other workshop artefacts
```

## Fact-Finding Methods Used

As required by the course guidelines, at least two formal fact-finding techniques are employed and evidenced here:

| Technique | Evidence Location |
|-----------|------------------|
| Structured Client Interview | `client-interviews/` |
| Competitive Analysis | `competitive-analysis/` |
| Document Analysis | `document-analysis/` |

All artefacts are committed to this repository within 24 hours of the relevant session or activity.

## Branching & Contribution

Please read [CONTRIBUTING.md](./CONTRIBUTING.md) before making any changes.

Key rules:
- `main` is protected. All changes must go through a Pull Request with **at least 1 approving review**.
- Use `draft/<document>` branches for active work (e.g. `draft/competitive-analysis`).
- Use `fix/<issue-number>` branches for corrections (e.g. `fix/17`).
- All commit messages must follow the Conventional Commits convention (see CONTRIBUTING.md).
